# Stage 4 计划：Q4_K_M 线程数实验（STAGE4_PLAN v1，正式结果产生前冻结）

机器可读计划：`configs/stage4_plan.json`（plan_id `stage4_plan_v1`，
纳入 `datasets/frozen_hashes_stage4.json`）。分析修订见
`docs/stage3_analysis_revision.md`（独立交付，不在本计划范围内改动正式题/评分）。

## 研究问题

在本机上，Qwen2.5-0.5B-Instruct **Q4_K_M** 的提示处理速度、生成速度与
实际请求延迟如何随**统一 CPU 线程数** T ∈ {1, 2, 4, 8, 16, 32} 变化？

**选择 Q4_K_M 的理由**：Stage 3 中该版本文件最小（491,400,032 B）、
tg64 观测速度最快——作为系统参数实验对象；
**不把任何"质量等价"结论作为选择理由**。

**线程语义**：32 为使用 SMT 逻辑线程的实验点，不称"32 物理核"；
实验前已复核硬件为 AMD Ryzen 9 9955HX 16C/32T（`stage4_preflight` 实时核对，
不一致即停止）。唯一变化因素：server `-t T -tb T`；bench `-t T`（pp/tg 共用），
属**统一线程预算实验**，不研究两类线程独立调优；
不同时改变 CPU 亲和性、优先级或功耗策略。

## 固定配置（configs/stage4_config.json）

模型与后端指纹固定；CPU-only、`-ngl 0`、单进程、`--parallel 1`、串行请求；
`-c 1024 -b 2048 -ub 512 -ctk f16 -ctv f16 -fa off -lm mmap --cache-reuse 0`；
请求体 `cache_prompt=false`（每次启动后缓存检查核实）；
temperature=0、top_p=1、seed=42、max_tokens=96、冻结提示模板。
bench 无 `-c` 参数（不虚构）；**加载模式**：server 显式 `-lm mmap`；
llama-bench 无 `-lm`，为其内部默认（auto/mmap 类）——两条路径分别如实记录，
不宣称统一。T=4 为本阶段同期重测基准；Stage 3 的 T=4 仅作旁证，不合并。

## 矩阵 A：固定工作量微基准

- 6 档 × 5 轮 = **30 次 bench 进程启动**（内部 `-r 1`），每次同时产出
  pp256 / tg64 / pg256+64 三个条目 → **90 个测量值**；
- 保留默认 warmup（不计入测量）；pg 继续称**组合指标**；
- 每轮包含全部 6 档，档位顺序由种子 20261004 预生成
  （见 `stage4_plan.json.round_orders`），禁止恒按 1→32 递增。

## 矩阵 B：实际请求性能

- 固定题序 dev-001, 003, 004, 007, 009（冻结开发集）；
- 6 档 × 5 轮 × 5 题 = **150 条计时请求**；30 次独立服务启动；
- 每次启动：预热 1 条 + 缓存检查 2 条，单独记录，**不混入 150 条**；
- 保存：逐题输出、实际输入/输出 token 数、后端 timings、端到端时间、
  启动/初始化区间、峰值工作集（采样）、清理结果；
- 输出及其长度随线程档变化时**如实报告**，不隐藏在速度比较里；
- **本矩阵不作为新增正式质量样本**（quality_sample=false）。

## 执行与恢复保障

- 独立 `stage4_preflight`：后端**全部** exe/DLL 指纹 + 实时 `--version`
  核验（b11347/5fc4f3c8c）+ 模型 SHA256 + 硬件复核 + 冻结清单
  （`frozen_hashes_stage4.json`，含后端全量指纹与来源清单本身）；
- 每个运行单元验证：预热/缓存检查、预期请求/负载数量、HTTP 状态、
  输出结构、性能有效性、参数生效、清理确认——**执行完整、指标有效、
  清理成功分别记录**，不无条件写 ok=true；
- 超时：严格 `/slots` 检查（空列表/结构异常/解析失败一律不算确认空闲）；
  无法确认则终止本程序启动的进程，单元记 failed，剩余题记 not_attempted，
  按预注册规则继续下一单元（新服务）；bench 超时/中断保留已有
  stdout/stderr 与清理结果；
- 恢复：`--resume <run_id>`；恢复前核对模型/配置/计划/冻结清单/依赖指纹；
  只跳过 marker 存在且 `execution_complete=true` 的单元；不完整单元保留
  `*_partial.json` 证据后整单元重跑；汇总从落盘记录重建，**不用 0 填充**；
- 资源：测量前后资源快照（所有档位监测方式一致，避免监测本身成为负载）；
  CPU 未满载≠无干扰；不据速度好坏删除或选择重跑；资源冲突按冻结规则处理。

## 分析与推荐规则（预注册）

- 每档每工作负载：5 轮原始值、均值、样本标准差、变异系数；
- 加速比以**本阶段 T=1** 为基准；如报按线程归一化的效率，
  说明它不是 CPU 利用率，且 SMT 逻辑线程≠物理核；
- HTTP 按题分别统计，并用"每轮五题平均"的 5 轮统计表示固定任务组合延迟；
- 内存与启动耗时按独立服务进程统计（每档 5 个）；
- pp/tg/pg/实际任务延迟**分别报告最佳观测档位**；
- 推荐规则：若较少线程档均值距最佳观测均值 ≤3%，优先推荐较少线程，
  同时展示波动与配对轮次差异——3% 是实用阈值，**不是统计等价证明**；
- 不预设 16/32 必然更快；瓶颈机制只能按证据强度提出假设
  （未测带宽/频率/温度不得写成已证实事实）；
- 适用范围：本机、Q4_K_M、b11347、固定负载；不外推到长上下文、
  大模型或多请求并发。
