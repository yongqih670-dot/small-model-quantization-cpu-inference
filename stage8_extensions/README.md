# Stage 8　本机推理延迟与分类标签位置复验

2026-11-06 在同一台 Ryzen AI 9 H 365 笔记本上依次完成三项实验。Q4 关闭内置预热后，启动到第一段可见回答平均缩短 28.4 ms。固定输出 32 个 token 时，Q4 在两档较短输入上耗时最低，长输入下 Q4 与 Q8 的领先顺序随轮次变化。三种量化版本在多数新分类题上随选项顺序改变回答。

环境为 Windows 11、10 核 20 线程、31.29 GiB 内存，使用官方 llama.cpp b11347 CPU 后端与经 SHA256 核验的 Qwen2.5-0.5B-Instruct GGUF。固定 4 线程、上下文容量 1024、单 slot、mmap。全部 30 次正式服务进程启动前和结束后均记录为接通电源。Stage 7 在电池供电下进行，本文所有性能比较均使用本轮同机观测。

## A　预热如何改变首个答案的等待时间

Q4 每轮开、关内置预热各启动一个新进程，6 轮交替先后顺序，共 12 次正式启动。每次均先在计时外预读模型文件。客户端记录收到第一个含非空白回答文本的流式事件，忽略只有角色信息的事件。第一、第二请求固定使用不同开发题；每种设置内的同一题及其生成参数完全相同。以下为 6 次均值 ± 样本标准差，单位 ms。

| 时段 | 开启预热 | 关闭预热 | 轮内差值均值（关减开） |
|---|---:|---:|---:|
| 启动 → 健康检查成功 | 567.9 ± 13.7 | 530.8 ± 5.4 | -37.1 |
| 首次请求发起 → 首段可见文字 | 373.1 ± 7.2 | 381.8 ± 2.4 | 8.7 |
| 启动 → 首段可见文字（主指标） | 941.1 ± 17.2 | 912.7 ± 7.3 | -28.4 |
| 首次请求发起 → 完成 | 394.5 ± 6.9 | 403.0 ± 2.0 | 8.5 |
| 第二次请求发起 → 首段可见文字 | 380.2 ± 8.0 | 373.1 ± 10.9 | -7.1 |

关闭预热使服务平均提前 37.1 ms 就绪，但首个请求从发出到见字平均多花 8.7 ms。两者合计，6 轮中从启动到见字均更快，缩短范围 12.7–53.5 ms。本机在预读文件后启动 Q4 并立即发送短请求时，可以关闭预热以缩短第一次可见等待。两种配置对每个固定提示输出相同；两道题均答“未提供”，其中 dev-001 的金标为“周雨桐”。本项计时不以回答正确为验收条件。

## B　输入长度如何改变量化版本的速度排序

三种模型处理相同 token ID 序列的 64、256、768 长度前缀，原生 completion 接口每次强制生成 32 个 token。每格 5 轮独立启动，共 45 条计时请求；同一轮、同一模型的三个长度共享一次已暖机的进程。后端逐条确认实际输入和生成长度，以及零缓存命中。端到端时延包括本机 HTTP 往返和响应解析。速度以 token/s 计，以下均为均值 ± 样本标准差。

| 量化版本 | 输入 token | 端到端 ms | 提示处理 token/s | 生成 token/s |
|---|---:|---:|---:|---:|
| Q4_K_M | 64 | 476.5 ± 11.1 | 518.3 ± 48.2 | 90.7 ± 1.2 |
| Q4_K_M | 256 | 852.4 ± 34.7 | 545.0 ± 33.8 | 85.1 ± 2.9 |
| Q4_K_M | 768 | 1985.0 ± 48.7 | 484.6 ± 16.4 | 81.5 ± 1.3 |
| Q5_K_M | 64 | 596.9 ± 9.8 | 285.7 ± 13.3 | 86.9 ± 1.6 |
| Q5_K_M | 256 | 1245.8 ± 12.3 | 297.8 ± 2.6 | 84.3 ± 0.6 |
| Q5_K_M | 768 | 3108.1 ± 27.6 | 284.2 ± 3.2 | 79.9 ± 0.7 |
| Q8_0 | 64 | 565.1 ± 21.6 | 496.0 ± 74.8 | 73.9 ± 1.1 |
| Q8_0 | 256 | 901.3 ± 15.4 | 555.3 ± 26.0 | 73.8 ± 3.3 |
| Q8_0 | 768 | 1958.5 ± 67.7 | 514.2 ± 19.8 | 68.7 ± 1.0 |

64 和 256 token 下，Q4 的平均端到端延迟分别为 476.5 和 852.4 ms。768 token 下，Q8 的提示处理更快（514.2 对 Q4 的 484.6 token/s），Q4 的生成更快（81.5 对 Q8 的 68.7 token/s）。在固定输出长度下，Q8 的端到端均值低 26.4 ms，5 轮中 Q8 快 3 轮、Q4 快 2 轮。Q5 在三档输入上都花费最多时间，主要可观察差异在提示处理速度。该结果适用于这里的同一语料前缀、固定输出长度及 4 线程配置；更长输出、其他任务和线程数需另测。

## C　20 道新题上是否仍有标签位置偏好

沿用 Stage 6 的五种二分类规则，重新编写 20 条情境，每个标签域 4 题，金标对半分配。每题只交换提示中两个候选标签的顺序，对三个模型共发出 120 个请求，使用同一固定乱序。两种顺序均各有 10 道题的正确标签排首位。所有响应均正常结束、严格匹配某一标签，120 条缓存命中计数均为零。下表前四列按原始题目计数，每行合计 20。

| 量化版本 | 两序均选首位 | 两序均选次位 | 两序选同一标签 | 至少一序无效 | 原序答对 | 反序答对 |
|---|---:|---:|---:|---:|---:|---:|
| Q4_K_M | 17 | 0 | 3 | 0 | 9/20 | 12/20 |
| Q5_K_M | 16 | 0 | 4 | 0 | 10/20 | 10/20 |
| Q8_0 | 15 | 0 | 5 | 0 | 9/20 | 10/20 |

例如，new-04 是一则失物招领消息，金标为“正常信息”。把“垃圾信息”放在首位时三个模型均回答“垃圾信息”，交换位置后三个模型都改答“正常信息”。这也解释了为何只看整体正确率会漏掉位置效应：Q5 两种顺序都答对 10/20，但有 16 道题在交换后跟着首位改变了答案。Stage 6 中 Q4、Q5、Q8 两序都选首位的计数分别为 8/10、8/10、7/10，本次新题上观察到同方向行为。两次样本不同，仅作描述性复验；结论限定这组中文二分类题和提示格式。

## 本机复现

在 Windows 环境中准备 Python 3.12 和 psutil。按 [Stage 7 说明](../stage7_local/README.md)将三个模型放入 `stage7_local/assets`，并将官方 b11347 ZIP 留在该目录，同时解压到 `stage7_local/assets/backend`。本组实验直接调用官方后端。请从本目录运行；每次试跑和正式执行均创建独立目录，正式运行需显式绑定同一程序和输入哈希下通过的试跑。

```powershell
python experiment_A.py pilot
python experiment_A.py formal runs/<刚产生的A试跑目录>
python experiment_B.py pilot
python experiment_B.py formal runs/<刚产生的B试跑目录>
python experiment_C.py pilot
python experiment_C.py formal runs/<刚产生的C试跑目录>
```

只复核本次已提交的结果可直接运行以下命令，无需下载模型。脚本按原始响应及时间戳重算统计，输出至新目录 `recomputed`。新采集时将参数换成对应正式目录；可用 `--output` 指定其他新目录。

```powershell
python analyze.py runs/A_formal_210159_1b2177 runs/B_formal_210313_349d9f runs/C_formal_210537_87f5f7
```
